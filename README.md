# Text Matcher — поиск товара по запросу

Программа ищет наименование товара в базе данных по запросу пользователя,
набранному в терминале:
TF-IDF по **символьным триграммам** → kNN (косинус) + логистическая регрессия.

Ключевой пример из задания:

```
>>> хочу купить вешь
Очистка  : «vesh»
НАЙДЕНО  : Super vesh 3000  [Коллекционный товар]  9990 руб.
```

## Запуск

```bash
pip install -r requirements.txt

python main.py              # обычный интерактивный режим
python main.py --demo       # прогнать несколько демо-запросов и выйти
python main.py --rebuild-db # пересоздать базу заглушек
```

> При первом запуске автоматически создаётся `products.db` (SQLite) с
> **300 наименованиями-заглушками**, среди которых «Super vesh 3000».
> Часть названий в БД намеренно «грязная» (КАПС, двойные пробелы, `!!!`,
> `– NEW`, `/// актуально?`) — так видна работа очистки.

## Как это работает

1. **Очистка текста** (`preprocess.clean_text`)
   - нижний регистр, удаление пунктуации/эмодзи/лишних пробелов;
   - удаление стоп-слов («хочу», «купить», «мне», «где», «!!!» и т.д.);
   - **транслитерация кириллицы → латиница**, чтобы «весь»/«веш» сопоставлялось
     с латинским «vesh» в названии `Super vesh 3000`.
2. **Признаки** — TF-IDF (`TfidfVectorizer`) с `analyzer="char"`, `ngram_range=(3, 3)`,
   то есть разбиение текста на **символьные триграммы** (устойчиво к опечаткам).
3. **Поиск** — kNN (`NearestNeighbors`, метрика `cosine`) по корпусу названий.
4. **Классификация** — `LogisticRegression` по 300 классам (товарам), обученная
   на **синтетических запросах**: выпадение слов, опечатки, случайный мусор.
5. **Решение** — голосование классификатора и kNN + пороги уверенности;
   при низкой уверенности — «НЕ НАЙДЕНО» с похожими кандидатами.

## Файлы

| Файл | Назначение |
|---|---|
| `preprocess.py` | очистка текста, стоп-слова, транслитерация |
| `database.py` | SQLite-база: генерация 300 заглушек, загрузка |
| `matcher.py` | ML-модель: TF-IDF триграммы + kNN + LogReg |
| `main.py` | интерфейс терминала |
| `products.db` | база данных (создаётся автоматически) |

## Качество модели

- accuracy на обучении: **0.947**, на тесте: **0.884**
- независимая проверка на 3000 свежих синтетических запросов:
  top-1 **0.877**, правильный ответ в топ-3 суммарно **~0.95**,
  отказов («не найдено») — 1.7%, промахов — 3%
